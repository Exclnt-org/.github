# Contributing to Exclnt

Thank you for your interest in contributing to Exclnt.

We welcome contributions from developers and community members who want to learn, build, share knowledge, and improve our projects.

## Before Contributing

Before making changes, please:

1. Read the repository documentation.
2. Check existing issues and pull requests.
3. Open an issue if you need to discuss a significant change.
4. Make sure your contribution follows the project's guidelines.

## Development Workflow

The general workflow is:

```text
Fork / Repository Access
        ↓
Create a Branch
        ↓
Make Changes
        ↓
Test Changes
        ↓
Commit
        ↓
Push
        ↓
Create Pull Request
        ↓
Review
        ↓
Merge
```

## Branch Naming

Use descriptive branch names.

Recommended formats:

```text
feature/<name>
fix/<name>
docs/<name>
refactor/<name>
chore/<name>
```

Examples:

```text
feature/user-authentication
fix/login-validation
docs/update-readme
refactor/api-service
chore/update-dependencies
```

## Commit Messages

Keep commit messages clear and descriptive.

Recommended format:

```text
<type>: <description>
```

Examples:

```text
feat: add user authentication
fix: resolve login validation error
docs: update installation guide
refactor: simplify API service
chore: update dependencies
```

Common types:

* `feat` — new feature
* `fix` — bug fix
* `docs` — documentation changes
* `refactor` — code restructuring
* `test` — tests
* `chore` — maintenance
* `style` — formatting or style changes

## Pull Requests

Before opening a pull request:

* Make sure the code works as expected.
* Test your changes locally.
* Keep the pull request focused.
* Explain what was changed and why.
* Link related issues when applicable.
* Avoid unrelated changes.

Pull requests may be reviewed before being merged.

## Code Quality

Contributors are expected to:

* Follow the project's existing coding conventions.
* Keep code readable and maintainable.
* Avoid unnecessary complexity.
* Add tests when appropriate.
* Update documentation when necessary.

Each repository may have additional technical requirements.

## Reporting Bugs

If you find a bug, create an issue using the Bug Report template.

Include:

* A clear description of the problem.
* Steps to reproduce it.
* Expected behavior.
* Actual behavior.
* Relevant environment information.
* Screenshots or logs when useful.

## Suggesting Features

For feature requests, use the Feature Request template.

Explain:

* The problem you want to solve.
* The proposed solution.
* Possible alternatives.
* Additional context.

## Respect the Community

Contributors are expected to communicate respectfully and constructively.

Please review our [Code of Conduct](CODE_OF_CONDUCT.md) before participating.

## Questions

If you are unsure about something, open an issue or discuss it with the project maintainers.

Thank you for helping build Exclnt.
